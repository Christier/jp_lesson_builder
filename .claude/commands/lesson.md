# 今日の教材を作る

対象日: $1 （空なら !`date +%Y-%m-%d` を使う）

@CLAUDE.md のルールに従って、次の順に進めること。**途中を飛ばさない。**
コマンドはすべて `./lesson.sh <コマンド> <対象日>` で実行する（Windows の Git Bash でも動く）。

## STEP 1 — 下調べ（コードを書く前に必ず）

1. `data/themes.json` を読み、**既出の会話テーマと直近3回の配色**を確認する。
2. `./lesson.sh review <対象日>` を実行し、**要再訪・一度きりの語彙**を把握する
   （「次回教材で優先的に再登場させる候補」から2〜3語を今日の教材に織り込む）。
3. `data/vocab-index.json` を読み、**既出語彙**を頭に入れる（後で復習リンクを張るため）。
4. ユーザーから会話テーマの指定があればそれに従う。なければ、
   ニュース・季節・`candidates` から未使用テーマを1つ選び、**選んだ理由を一言で述べる**。

## STEP 2 — ニュース取材

WebSearch / WebFetch で**対象日の実際の報道**を集める。NHK・日経・時事通信・
気象庁・各省庁発表などを当たる。`notes/<対象日>-news.md` が既にあれば（/news の成果）まずそれを使う。

- 分野を必ず散らす（気象/経済/IT/政治/社会/スポーツ文化 から3分野）
- 1本は IT・セキュリティ・AI など**ユーザーの本業に関わる分野**を入れる
- 1本は**場面会話の伏線**になるものを選ぶ
- 各本について「発表時刻・具体的な数値・固有名詞・背景・見通し・当事者コメント」を控える
- その他の見出しを5本、時刻付きで拾う

**記憶から書かない。数値は原文表記のまま写す。**

## STEP 3 — 雛形作成と執筆

```bash
./lesson.sh new <対象日>
```

生成された `content/<対象日>.json` を埋める。ニュース3本分の枠（ID t1a / t2a / t3a 系）は用意済み。
マークアップ記法・品質基準は @CLAUDE.md を参照。特に：

- 語彙には必ずIT業務への転用例を添える
- 既出語には「（7/2の復習）」のような復習リンクを書く
- 会話は18〜20ターン、8割以上のターンに解説(note)を付ける。セリフで使えるのは `{{b:}}` `{{k:}}` `{{br}}` のみ
- SVG図解を2〜4枚、`illustrations[].svg` に直接書く（viewBox="0 0 220 150" が基準）
- 総合チャレンジは中国語メモ→日本語通訳、「添削します！」で締める
- バッジの「〇ターン」「ニュース〇本」は実際の数と合わせる
- 最後に `index`（記録用のテーマ名と、今日の重要語彙・文法 5〜10個）を書く

## STEP 4 — ビルドと検証

```bash
./lesson.sh check <対象日>      # build → validate
```

**ERROR が残っている間は完成ではない。** JSONを直して再実行する。
WARN は内容を見て、意図的なら無視してよい（無視した理由を報告に一言書く）。
INFO の「既出語」に挙がった語は、ツールチップに復習リンクが書けているか確認する。

## STEP 5 — 記録

```bash
./lesson.sh record <対象日>
```

`index` をもとに `data/themes.json`（used への追記・候補からの除外）と
`data/vocab-index.json`（新語の追加・既出語への日付追加）を自動更新する。
**data/ の JSON は手で編集しない。** ERROR が残っていると記録されない。

## STEP 6 — 報告

ユーザーに向けて日本語で：
1. ニュース3本の要旨（数値と出典を添えて）
2. 会話テーマと、今日身につく「日本語の型」
3. 拡張学習の見どころ
4. 生成ファイルのパス（`./lesson.sh open <対象日>` で開ける）
を簡潔にまとめる。長い前置きは不要。
